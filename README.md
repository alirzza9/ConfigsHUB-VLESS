# ConfigsHUB VLESS — Private

جمع‌کننده VLESS فقط از کانال تلگرام **ConfigsHUB**، با تست واقعی و ساب تفکیک‌شده بر اساس کشور.

> این ریپو **پرایوت** است. لینک خام `raw.githubusercontent.com` برای ریپوی پرایوت بدون احراز هویت کار نمی‌کند. برای استفاده از ساب‌ها یا فایل را از همین ریپو دانلود و ایمپورت کنید، یا از لینک خام با توکن شخصی (Fine-grained PAT با دسترسی Contents: Read فقط برای همین ریپو) استفاده کنید:
> `https://<TOKEN>@raw.githubusercontent.com/alirzza9/ConfigsHUB-VLESS/main/sub/vless-all.txt`
> اگر کلاینت شما userinfo را از URL حذف می‌کند، روش دانلود و ایمپورت را استفاده کنید.

## ساب‌ها (Base64)

| ساب | فایل |
|---|---|
| همه کانفیگ‌های سالم | `sub/vless-all.txt` |
| فقط کانفیگ‌های سالم از ایران (For-Iran) | `sub/vless-for-iran.txt` |
| هر کشور جدا | `sub/vless-<cc>.txt` مثل `vless-de.txt` ، `vless-ca.txt` |

نسخه متنی (غیر Base64) هر فایل با پسوند `-plain.txt` در همان پوشه است.
`sub/report.json` و `sub/report-iran.json` آمار هر اجرا را دارند.

## چطور تست می‌شود (روش پروژه‌های موجود، نه اختراع دوباره)

روش دو مرحله‌ای مثل v2all / MK_XRAYchecker / XrayChecker:

1. **جمع‌آوری:** فقط `t.me/s/ConfigsHUB` (با صفحه‌بندی `?before=`)، فقط `vless://`، حذف تکراری‌ها. کانفیگی که هر جاش `pages.dev` یا `workers.dev` باشد جمع نمی‌شود.
2. **مرحله ۱ — TCP ping:** اتصال به host:port با تایم‌اوت ۴ ثانیه، ۱۰۰ کارگر موازی. باز بودن پورت به‌تنهایی دلیل سالم بودن نیست.
3. **مرحله ۲ — تست واقعی Xray:** برای هر بازمانده یک کانفیگ موقت Xray ساخته می‌شود، یک SOCKS محلی بالا می‌آید و واقعا از داخل پروکسی به `https://www.gstatic.com/generate_204` درخواست فرستاده می‌شود (تایم‌اوت ۸ ثانیه). فقط جواب ۲۰۰/۲۰۴/۳۰۱/۳۰۲ قبول است و بر اساس سرعت مرتب می‌شود. کانفیگ‌های قطع‌شده حذف می‌شوند.
4. **For-Iran:** برای سرورهای یکتای سالم، با API رایگان Check-host (بدون کلید) از نودهای زنده ایران TCP تست گرفته می‌شود (`/check-tcp` و بعد `/check-result`). اگر حداقل نصف نودهای ایران که جواب دادند زمان برگرداندند، کانفیگ وارد `vless-for-iran.txt` می‌شود. محدودیت صادقانه: این TCP از ایران + تست کامل روی رانر است، نه هندشیک کامل VLESS از داخل ایران.
5. کانفیگ‌های با رمزنگاری جدید (مثل mlkem) که Xray فعلی تستشان نمی‌کند، مرده حساب نمی‌شوند و جدا در `sub/vless-unsupported.txt` می‌مانند.

## فاصله زمانی اجرا

بررسی پروژه‌های دیگر (۲۰۲۶-۱۰-۳۱):

| پروژه | فاصله |
|---|---|
| V2RayRoot | ۳۰ دقیقه (فقط جمع‌آوری) |
| MhdiTaheri | ۶۰ دقیقه (فقط جمع‌آوری) |
| FreeVPNNodes | ۲ ساعت |
| Airport-Free | ۳ ساعت |
| v2all | ۶ ساعت (با تست واقعی) |
| tiagorrg vless-checker | ۳۰ دقیقه (فقط TCP) |
| mrvcoder (قدیمی) | ۵ ساعت |

**این پروژه: هر ۳ ساعت** (`0 */3 * * *` UTC) + اجرای دستی با `workflow_dispatch`.
دلیل: چون ریپو پرایوت است، دقیقه‌های رایگان GitHub Actions در طرح Free ماهانه ۲٬۰۰۰ دقیقه است (ریپوی پابلیک نامحدود است). یک اجرای کامل اینجا حدود ۳ تا ۵ دقیقه طول می‌کشد، پس هر ۳ ساعت حدود ۹۶۰ تا ۱٬۲۰۰ دقیقه در ماه می‌شود و حاشیه امن دارد؛ هر ۳۰ دقیقه حدود ۵٬۷۰۰ دقیقه در ماه می‌شد و از سقف رد می‌کرد. اگر ریپو روزی پابلیک شد، می‌توان فاصله را به ۳۰ دقیقه رساند.
